# 家具爆品雷达

基于卖家精灵数据监控美国站家具，识别增长、持续热销与异常商品，汇总开发方向，生成加密报告并推送钉钉。

每14天运行一期，每月调用上限2,000次；每天北京时间08:00检查是否到运行日期。

## 1 商品归类

每个商品只设一个主标签，按 **评分偏低 → 异常 → 突然爆火 → 潜力 → 持续热销 → 观察** 的优先级归类，其他符合条件可作附加标签，避免风险商品混入正向推荐或重复计数。

例如，低评分商品即使暴涨仍归低评分；评分合格但异常分达线则归异常；同时符合爆火、热销时归爆火，可附“长期头部”。

“上升中”只附加于观察或热销商品。**增长商品 = 突然爆火 + 潜力 + 上升中**，用于外观分析和开发方向，排除低评分、异常商品。文字简报只解释程序结果，不决定分类、分数或金额。

## 2 采集范围与比较口径

### 哪些商品进入候选

仅看美国站家具、办公家具中的板材、实木、铁木柜桌、床架和置物架，排除沙发、床垫、椅子、软包、布艺抽屉、塑料和配件。先筛子类目，再筛标题；面料词结合品类，配件词结合家具名词位置判断。子类目至少800个商品，最多追踪30类。

**取值理由：** 800避免类目过窄；30类控制成本，集中覆盖适合开发的市场。

机会候选按父体去重，须满足 **近30天销量至少300件，或销售额至少4万美元**，并满足以下任一初筛条件：

- 比约28天前保存的近30天名单销量增长至少15%。
- 上架不超过180天且销量未跌。
- 用相隔约14天的两份名单估算短期日销，达到较早名单日均的1.3倍。

新进名单没有旧记录时可保留候选，但不能认定过去零销量。

无合适基准时，用上月名单或21～52天前快照：距报告日21～23天增长线10%，24～36天15%，37～52天10%；月度基准下，近7天BSR（销售排名，越小越好）改善至少20%也可初筛。月销量按月天数统一口径，更换代表子体仍按父体匹配。**名单差额只用于初筛，正式入榜须查日数据。**

**取值理由：** 300件/4万美元兼顾走量款与高价款；15%、1.3倍及分档10%先保留增长机会，再用日数据排除误入。

采集优先级：上期爆火、潜力、异常最多300个 → 子类目头部30个 → 初筛机会，总池上限3,000。新进名单优先查近7天BSR改善至少20%的，其余按旧基准增长与短期持续性排序。月度发现取各类销售额前50；新品补查取销量最大的12类，每类最多30个、月销售额至少2万美元。

同类目相邻两个月至少5个共同商品、其中至少50%月销量完全相同，视为名单可能未更新完，重拉该类目，不能解释为销量稳定。

**取值理由：** 至少5个且一半相同，避免一两个巧合触发重拉；采集名额控制调用量，不代表证据强弱。

### 窗口与数据有效性

- **评分**：至少4.0分；已知评论少于100条时至少4.2分。无评分不直接判低分，评论数未知用4.0线。优先取最近日数据评分，缺失再用名单。
- **日期**：日数据落后“批次最新数据日、判定日”中较晚者超过2天，不判爆火、潜力或上升中；整批过期则停止发布。实际刷新商品须达到计划的60%，且至少1个。
- **窗口**：均以商品数据截止日向前算。爆火用近7或14天，与各自紧邻的旧28天比较；潜力、上升中用近28天与再之前28天比较，窗口不重叠。“上期报告”不等于旧28天。
- **缺失与零**：缺失不能补0。旧期有有效在卖数据就取其日均；没有时，须至少7个明确零日、其余非大促有效销量也全零，才认零基准。
- **月趋势**：只看已结束自然月，缺月留空；按真实月份间隔拟合ln(月销量+1)，换算整段平均月增长率，不要求每月分别过线。不足2个有效月不计算；新品累计销量另见第6节。

**取值理由：** 4.0设质量底线，少评论用4.2留余量；2天容许延迟，60%保障覆盖。7/14天及时发现起量，28天覆盖4周以减少偶然性。

### 对比期怎样排除疑似断货

为避免把恢复供货误判为新需求，旧期按正常在售日比较。**剔除只影响计算，不删除原始记录；近期低销量、零销量仍保留。**

1. 旧期日均跳过BSR缺失或≥1,000,000的日子，作为疑似未正常在售，不代表确认断货。
2. 潜力、上升中另跳过连续至少3天明确零销量的整段；按原始日历判断，大促不打断零销量连续性。
3. 旧期大促日符合在卖条件仍计在卖天数，但比较日均时排除确认的大促日。
4. 旧期有效在卖不足14天须标注，不一律取消增长分类；月增量归零条件见第9节。

**取值理由：** BSR百万线、连续3个零日提供停售线索；7个明确零日防止把缺数当零；14天为旧28天的一半，提示基准偏短。

例如，旧28天断货20天，其余8天每天10件，近期也每天10件：实际是10件对10件，不应因旧期断货算出增长。

### 大促、大盘与销量修订

**大促日**：选前14天数据覆盖至少70%、销量中位数至少3件的商品。当日至少40个合格商品，其中至少30%销量达到自身基准1.8倍，才认核心大促日；相邻日冲高占比至少15%可延伸，登记活动也须15%数据印证。日度比较排除确认的大促日，不另作季节调整。

**取值理由：** 70%覆盖、40个样本减少缺数和小群体干扰；1.8倍加30%要求放量明显且普遍，15%接住较弱延续。

**大盘倍数**：同类目至少10个共同商品，将销量变化折成28天跨度后取中位数，最高2倍。大盘上涨时，商品销量倍数先除以大盘再过线，例如3倍÷1.5倍=2倍；大盘下跌不放宽门槛，从零起量不作相除。

**销量修订**分两步，均通过才可校正：

1. 比较同批商品、同一天销量在两次获取中的变化：至少30个共同商品、历史下调至少2%，才估计系数及受影响天数。系数=改后÷改前销量，如0.8表示降至80%。
2. 检查近期偏高：取“最近受影响天数日均÷再之前18天日均”的商品中位数；日期前移14天再算一次，前者÷后者须达到`1+(1/历史下调系数−1)×0.5`。前后须有至少30个共同商品的有效比值；系数0.8时，确认线1.125。

`correct`模式将受影响近期销量乘系数，重算分类和金额；证据不足保留原值并提示。`tag`模式只提示可能变化，不改金额和排序。

**取值理由：** 大盘10个、上限2倍防个别值抬高门槛；修订30个、下调2%防小范围抖动。确认线取历史偏高幅度的一半（0.5），兼顾漏检与误校正；销量仍乘完整下调系数。

<a id="rule-03"></a>

## 3 突然爆火、潜力与上升中

三类均须通过评分、异常及时效检查，排除已识别的断货恢复、短时脉冲和近期回落；原始记录保留。

### 突然爆火

近7天、近14天分别检查全部条件，任一合格即可；都合格时展示爆发强度较高的一组，不能只检查倍数最高的窗口。

普通增长须**全部满足**：近期日均至少3件；相对旧28天在卖日均至少2倍，扣上涨大盘后仍至少2倍；近期BSR中位数不超过旧期一半（0.5倍）。

旧基准已知、日均低于0.5件时走“从零起量”：近期日均须达到30件与“第4节类目月销量门槛÷30×25%”中的较高值；有旧BSR仍须检查改善，无旧BSR可免。上架不超过180天称新品爆发，超龄或年龄未知称老链接重新起量；已识别换链接者不得走此通道。

持续性取近7个非大促日，最多回看14个日历日：

- **排脉冲**：每天超过旧基准的正增量中，最大的2天贡献至少60%，则不确认爆火，从零起量也适用。
- 排除脉冲后，从零起量可确认；普通增长还须满足以下任一形态。
- **稳在高位**：至少5天销量达旧基准1.5倍，近3天日均为这7天日均的0.85～1.15倍。
- **仍在上涨**：这7天日均至少为前7个非大促日的1.15倍，且最后3天日均高于这7天日均。

价格中位数比旧期下降至少15%只标“降价驱动”，不单独取消入榜；量未达确认线只提示起量。

**取值理由：** 3件防小基数，2倍及排名减半要求明显增长；从零起量用30件/类目25%保障规模。2天占60%排尖峰，5天达1.5倍检验持续，±15%容许走平波动，周增15%确认上涨；降价15%提示价格驱动。

### 潜力与上升中

两类均以旧28天在卖日均为基准，检查近28天、近7个非大促日（最多回看14日），**两个销量倍数都须达线**；未知或零基准不能通过。

| 条件 | 潜力产品 | 上升中 |
|---|---|---|
| 上架与评论 | 上架30～180天；已知评论少于300条，未知不直接否决 | 不限 |
| 最近28天日均 | 至少2件 | 至少3件 |
| 两项销量倍数 | 扣上涨大盘后均≥1.2倍 | 扣上涨大盘后均≥1.3倍 |
| 月趋势 | 近3个已结束月中，上架月之后有至少2个有效月时，平均月增长率须≥15%；不足则标“尚未验证” | 不要求 |
| 其他限制 | 不得是老品换链接 | 只附加于未归爆火、潜力的观察或热销商品 |

**取值理由：** 30天积累观察，180天/300条限制成熟度；2件、1.2倍捕捉早期机会，不限年龄的上升中用3件、1.3倍提高要求。月增15%和最近一周再过线，防止旧涨幅撑榜。

例如，近28天增长50%，最近一周却只为旧基准1.05倍，两类均不成立。爆火、潜力按月增量排序，同额分别看爆发强度、增长幅度；增量见第9节。

## 4 持续热销

持续热销表示有规模且稳定，不要求增长。类目门槛取销售额、销量头部名单合并并按父体去重后的月销量第20名；不足20个取末位，无样本不设门槛。这是采集样本门槛，不是历史各月的全市场排名。

以下条件须**同时满足**：

1. 近4个已结束自然月至少3个月达到类目门槛；各计入月还须满足“销量≥150件或销售额≥2万美元”。
2. 近6个日历月已知月销量的CV≤0.35。CV=标准差÷均值，越小越稳；缺月留空，不要求6个月都有值。
3. 近3个月可算趋势时，平均月趋势≥−15%；无法计算不单独否决。
4. 近28天日均至少达到上述6个月“已知月份平均日均”的70%。

**取值理由：** 前20提供相对规模，150件/2万美元防小类目门槛过低；4个月达标3个月容许偶发波动。CV 0.35、月趋势−15%、近期70%兼顾稳定与正常起伏，排除明显衰退。

按6个月已知月销量均值降序。近期回落可保留热销并提示，但不再算增长。

**月度补判**：仅限未追踪日数据、与已追踪商品不同父体、连续6个月位于该类销售额或销量前50的商品。须有报告期有效近30天销量，以销量÷30估近期日均，再按大促、修订口径及上述条件判断。

补判不画日走势图、不判日度回落、不计日数据追踪数；异常分达线须归异常，可附“长期头部”。

**取值理由：** 连续6个月头部补足持续性证据，近30天检查防止只凭老成绩入榜。

## 5 回落、断货恢复与老品换链接

### 哪些走势算近期回落

以下任一成立，取消爆火、潜力、上升中；热销可保留并提示。比较排除大促日，缺失不补零：

- 近3天日均低于近28天最高连续3天日均的75%，**且**低于紧邻此前3天日均的90%。
- 近7天销量中位数低于此前7天的85%。
- 近7天峰值后连续至少3个有效观察日未回升，末日销量≤峰值70%。

**取值理由：** 75%加90%确认低于峰值且继续下降；周中位数85%看整周走弱，连续3次且降至70%补抓快速下滑，减少单日噪声。

### 怎样认定断货恢复

须**同时满足**：爆火旧基准期明确零销量或BSR达断货线的天数≥7天且≥有效窗口25%；再往前90天至少14个非零销售日；这些销售日的日均≥近期一半。满足则按恢复供货排除增长；缺数据不能当断货证据。

**取值理由：** 一周/四分之一确认断货明显压低基准；90天内14个销售日且达到近期一半，避免用零星历史认定恢复。

### 怎样识别老品换链接

表示新链接可能继承老链接的评论或销售基础。须上架≤180天，并满足以下任一：

- 累计评论÷本ASIN已观测累计日销量≥50%。
- 上述比例≥15%，**且**有任一证据：①开卖首周日均≥5件且≥近7天日均一半；②首次达到“5件、近7天日均一半”较高量级后，随后一周仍达该量级，前一周日均≤后一周10%；③有效抽查的近60天评论量，不到按累计评论和上架天数折算应有量的一半。

识别后不判潜力、从零新品爆发，不用继承评论给留评率、新品评论比加分；自身符合稳在高位、上涨或上升中仍可入选。旧期涉及开卖首周只标注，增量归零另见第9节。

**取值理由：** 50%要求较强评论存量，15%须另有快速起量或继承证据；5件/近期一半及前后10%约束跳变，减少误伤正常广告起量。

## 6 异常信号怎样计分

异常分是复核优先级，不是刷单概率。**≥3分进异常榜，≥5分列较高风险**，按总分、近28天日均降序；低评分仍优先归低评分。空榜不等于无异常，不能为填榜降门槛。

留评率=名单统计期新增评论÷同期销量；新品评论比=累计评论÷累计销量；评论增速=两次观察间新增评论÷同期销量。三者时段不同，含义重叠，须按表降权。

| 信号 | 触发条件 | 分值 |
|---|---|---|
| 留评率偏高 | 扣Vine后新增≥10条；留评率≥6%且≥类目中位数3倍 | +2 |
| 新品评论比 | 上架≤90天、总评论≥20条；扣Vine后累计评论÷完整累计销量≥10% | +2；留评率已计分则+1 |
| 评论增速偏高 | 扣Vine后新增≥10条；同期完整销量全零，或新增评论÷同期销量≥15%且≥类目留评率中位数3倍 | +2；前两项任一已计分则+1 |
| 评分跳升 | 比45天内前次有效观察提高≥0.2分，总评论≥50条 | +1 |
| 销量脉冲 | 近30天出现1～3天冲高，起点≥前28天销量中位数3倍且≥6件/天；之后间隔至少3天、最多看7天，已有销量日均回到基线1.3倍以下；非大促 | +1 |
| 评论集中 | 样本≥10条，评论最多的3天合计≥30%，且条数超过同样样本量、跨度下随机分布的99%参考上限 | +2 |
| 非验证购买多 | 至少10条评论有明确验证购买标记，其中未验证≥50% | +1 |

**取值理由：** 较强信号2分、辅助信号1分，3/5分区分复核优先级。6%加类目3倍兼顾绝对、相对异常；10%/15%要求明显偏高，10/20/50条及0.2分减少小样本误报；非验证过半仅加1分，避免单项定性。

评论集中须同时过占比、随机参考上限；“最多3天”不要求连续，99%参考值不代表99%概率刷评。

### 哪些证据不能加分

- 评论、销量须同一父体范围，不再除变体数。名单新增评论>总评论×1.05+5时不计留评率；确认评论继承或换链接时，不计对应留评率、新品评论比。
- 评论增速的旧评论数取此前45天最高值，无记录才用前次有效观察；如100→80→95不算新增15条。确认父体/变体合并时，不计相关评论增速。
- 观察间销量须每日完整、非负、有效，缺一天就不算比率，全零须有明确记录。新品累计销量须覆盖上架月至截止月已有销量；月度不齐改查上架日起完整日数据，仍不齐则不计，忽略未来月份。

### Vine怎样扣除

Vine是亚马逊官方免费试用评价，不能直接当异常。有效核查有Vine比例时按样本估计扣量；无可用比例且上架≤90天时，对累计前30条作可能Vine的保守扣减，**这是项目参数，不是平台政策**。

三项评论比率按各自时段扣除，不得每次对新增评论重复减30条。扣前达线、扣后未达线的新品仍保留待核查资格。Vine样本占比≥30%、变体合并、大促脉冲只作解释，不加异常分。

**取值理由：** 99%随机参考上限减少小样本误报；90天内预留30条给正常新品测评留余地，取得核查后改用实际比例。

<a id="rule-07"></a>

## 7 评论核查怎样使用

每期评论、父体/变体详情查询共用15次调用，其中5次预留给未上榜且异常分≥2分的候选，用不完归还其他核查。一次调用不等于一条评论，也不保证完成一个商品的全部补查。

评论数比前次上涨≥30%且缺有效详情核查时，先查父体/变体。其他查询依次为：可疑上榜 → 报告点名与开发参考 → 未上榜且≥2分 → 其他爆火/潜力 → 可能Vine扣减新品。同级按异常分、增长强度和销售额安排，并保障预留名额；未查不等于通过。

### 样本有效性

抽样条数与评论总量分开记录，不能把部分样本当全部评论。

- 查询、返回过滤采用同一截止日，取此前约60天最新评论。部分样本用“最早样本日至截止日”、至少7天算集中度；确认取全才按60天。日期过滤后全空，不记为新有效核查。
- 验证购买须明确真/假，缺字段不算未验证；至少10条明确标记才算比例。Vine比例要求全部样本都有标记。
- 零样本而总量非零或未知，不能证明无评论。旧核查缺标记样本数时不沿用其比例，但可保留有依据的条数、集中度。

### 时效与身份

核查取得日距判定日须为0～13天，满14天失效。若有样本截止日，距“判定日、商品数据日”较晚者也须0～13天；“何时查到”与“查到哪个日期”分开保存。

核查绑定当时父体、变体结构。父体改变，或变体数变化达到“2个、旧数量30%”较高值，原评论核查失效；如旧10个变体，变化至少3个达线。详情留前后结构，更新父体前留旧快照；保留同日评分变化，缺字段不覆盖有效值。

回放历史只用当时已取得的核查及商品身份，不得用后来结果给过去加分或豁免。

**取值理由：** 15次留5次防未上榜候选漏查；14天防旧证据长期沿用；60天/至少7天规范集中度窗口；变体同时变化2个、30%才失效，过滤微调。

<a id="rule-08"></a>

## 8 外观工艺与主材质

### 先分清两种对照

标题比较增长商品与全部月度头部，至少3个增长、20个头部。主图取势头前50个增长，对照最多40个非增长的持续热销商品，另补开发方向样本。两种来源分别说明，颜色优先主图。

每项外观特征须至少2个增长商品、2个已知品牌支持。未知品牌商品保留在占比分母，不得把不同ASIN当不同品牌。

| 分档 | 判断条件 | 可说明什么 |
|---|---|---|
| 更多 | 标题增长侧占比≥10%，且修正后≥头部1.3倍；或主图增长侧比对照高≥10个百分点 | 在对应样本中更突出 |
| 常见 | 未入更多，增长侧占比≥30% | 多个增长商品共有，不表示比对照多 |
| 也有 | 未入前两档，增长侧占比≥10% | 有支持，弱于常见 |

“高10个百分点”如40%−30%=10个百分点。标题占比倍数先作小样本修正：两组计数各加0.5、样本数各加1，避免头部零计数产生无限倍数。

有效标题、主图判断方向相反时，三档都不列。更多按占比差排序，两源支持适当前置；每维度最多6个更多、3个常见、6个也有。

其他结构化共性须≥2个商品、增长占比≥20%、修正倍数≥1.5，最多10条。关键词通常≥3个商品；增长样本<20时，改用“2、样本量15%向上取整”较高值；修正倍数≥2，最多15条。共现不等于这些特征导致增长。

### 主材质单独统计

每商品只取一个主材质，证据顺序为 **商品Material属性 → 标题明确材质 → 主图识别 → 标题笼统木质**。木纹不等于实木，缺属性不等于没有该材质。

增长、热销分组统计材质，未知项保留在分母，不套用外观“更多”结论。材质属性每期最多查30次，须注明来源，未查不能说已核实。

**取值理由：** 2个商品、2个品牌减少单卖家铺款影响；10%加1.3倍、或高10个百分点要求覆盖与差距。30%/10%区分支持强弱；50/40及展示上限控制成本、阅读量，不代表统计保证。

<a id="rule-09"></a>

## 9 开发方向、增量与成本

### 哪些类目形成方向

同类目≥2个增长商品、≥2个已知品牌才形成方向，按月增量总额降序，同额依次看品牌数、增长商品数、爆火数、势头。展示上限按配置，0为全部，摘要前5；无共同特征和明确材质时列原因，不拼凑画像，高增量缺画像另提示。

### 怎样和同类目头部比较

头部取该类月销量前30，排除增长商品及其同父体商品。须≥10个已知头部品牌才作相对比较，否则只列共同特征；其中≥10个品牌已识别主图时，两边都用标题+主图，否则都只用标题。

先算各品牌内部特征占比，再对品牌等权平均，防单品牌铺款主导结果。例如A品牌5/10个有、B品牌1/1个有，品牌均占比=(50%+100%)/2=75%。

- **比头部多**：≥2品牌支持，增长侧品牌均占比比头部高≥20个百分点，且≥头部1.5倍。
- **基本款**：≥2品牌支持，增长侧品牌均占比≥50%，且未入更多；对照不足称共同特征。每维度每档最多3项。
- **主材质**：品牌任一增长商品有该材质即算支持；须至少半数已知品牌且≥2品牌支持，不直接称头部优势。
- **价格与参考**：列有效售价最低～最高值，≥3个价格才给中位数。参考最多2个，须异常分0、来自不同已知品牌；不足少列，0分不等于已证实安全。

**取值理由：** 10个头部品牌降低偏差；高20个百分点且达1.5倍排除品类普遍特征；50%识别基本款，双品牌参考减少重复；摘要5个/每档3项方便执行，完整证据保留。

### 月销售额与月增量怎么算

估算月销售额 = 最近28天日均×商品售价×30。

估算月增量 =（最近28天日均−再之前28天在卖日均）×同一售价×30。

两项统一大促、修订口径。未知基准标“无法估算”，不计合计；可计算的负增量保留，以下情况增量按0计并注明原因：

1. 老品换链接，旧28天无在卖基准或在卖不足14天；基准未知仍优先标无法估算。
2. 从零起量归“老链接重新起量”；或上架>180天且旧28天在卖不足14天。
3. 仅恢复旧高位：在旧基准开始前56天内，取有效在卖≥14天的历史连续28天最高日均，近期未超过它。爆火用选中7/14天日均，其余增长用28天日均核对。
4. 无售价，无法算金额。

**归零只影响金额和排序，不自动撤销增长标签**，所以增长商品也可能无正月增量。

**取值理由：** 旧28天至少14天在卖保障老链接基准；回看56天防恢复销量主导排序；乘30统一月度量级便于比较，不是自然月实际收入。

### 包装与FBA费用

FBA为亚马逊配送费估算，必须用包装尺寸、重量，不能用组装尺寸。英寸长×宽×高÷1,728=立方英尺，再×0.0283168=立方米；重量统一磅。

体积、重量、费用分别按有值商品取中位数，样本数可不同；FBA占售价先逐商品算再取中位数。销量、金额、费用均标估算；利润另计采购、头程、佣金、仓储、广告、退货等成本。

<a id="rule-10"></a>

## 10 上期对比与发布

### 上期变化怎样归类

- **依旧爆火**：两期主标签均为爆火。
- **新进入**：上期不在该板块，本期进入；跨板块转入须注明。
- **不再爆火**：上期爆火，本期仍追踪但归观察或低评分；转潜力、热销、异常列对应变化。未追踪不能当回落。
- **月度补判**：此前未覆盖、本期靠历史名单判出热销，单列补判，不称刚热销。回看未追踪商品的上期须注明；上期待修订时须复核全部上期增长商品。

### 哪些数据问题只提示

以下仅提示数据风险，不替代板块判断：增长商品变体增加≥30%且≥2个；近30天名单、日销量均≥60件却相差≥2倍；近28天缺≥7天日数据。

近10天若至少40个合格样本、过去排名中位数≤30万，其中排名改善至旧值1/1.8的占比≥10%，连续≥2天，提示销量可能未修订，不直接改分类。

### 预算与发布边界

间隔14天、每月最多2,000次调用，剩余额度按本月剩余期数均分，单期最多2,500次。评论与详情核查15次、材质30次、月度名单补齐50次均为上限，计入总预算。

按北京时间自然月记账，共享密钥须给其他服务留额度。核心采集失败、刷新不足或整批过期时不发布新一期，保留旧报告、采集进度供重试。

**取值理由：** 14天/2,000次平衡时效、覆盖与成本；15/30/50防补查挤占日数据；2,500是单期保护上限，仍受月度剩余额度限制。

## 运行与部署

### 本地运行

安装Python 3.11，在仓库目录运行：

```powershell
python -m pip install -r requirements.txt
python -m radar demo
```

打开`out/demo/report.html`预览，演示不消耗接口调用。真实采集前，复制 [.env.example](.env.example) 为`.env`（已有则直接编辑），填密钥后运行`python -m radar run`。本地`site/`与GitHub线上历史分别管理。

| 密钥 | 用途与填写要求 |
|---|---|
| `SELLERSPRITE_SECRET_KEY` | 真实采集必填，取自[卖家精灵开放平台](https://open.sellersprite.com) |
| `REPORT_KEY` | 加密必填，用`python -m radar keygen`生成并备份 |
| `DINGTALK_WEBHOOK`、`DINGTALK_SECRET` | 推送必填；钉钉群加签机器人的Webhook地址、SEC开头密钥 |
| `DEEPSEEK_API_KEY` | 可选，取自[DeepSeek](https://platform.deepseek.com)，用于文字简报、主图识别；不填则用模板及非视觉证据 |

### GitHub自动部署

1. Fork仓库并启用Actions，把上述密钥填入仓库 **Settings → Secrets and variables → Actions → Secrets**。
2. 在 **Settings → Pages → Build and deployment**，把Source设为 **GitHub Actions**。
3. 在 **Actions → 家具爆品雷达 → Run workflow** 选`mode: run`；`force`忽略14天间隔，`notify`控制推送，`budget`覆盖本次调用上限。启用推送后可从钉钉卡片打开报告。

Windows也可安装GitHub CLI，`gh auth login`后运行`powershell -ExecutionPolicy Bypass -File scripts\setup_secrets.ps1`配置密钥；脚本读取`.env`，缺少`REPORT_KEY`时生成并保存。

多群推送：每群新增Secret `DINGTALK_ROBOT_1`至`5`，值为`Webhook地址,SEC密钥`，用英文逗号分隔；更多群须改工作流。

### 常用操作

| 目的 | 命令或入口 |
|---|---|
| 忽略间隔，真实采集并推送；会消耗调用 | `python -m radar run --force --notify` |
| 仅用已保存数据重生成，不重新采集 | `python -m radar rerender`；线上选`mode: rerender` |
| 补发最近一期通知 | `python -m radar notify` |
| 检查机器人与链接 | `python -m radar test-dingtalk --with-key` |
| 查看本地状态、全部命令 | `python -m radar status`、`python -m radar --help` |
| 验证代码，不调用真实服务 | 安装`requirements-dev.txt`后运行`python -m pytest -q` |

配置：`scope/discovery/pool`管范围与采集，`thresholds`管判定，`schedule/budget`管周期和预算，`llm`管模型，`report/notify`管报告与通知。报告保留60期，模型另计费。

## 故障恢复与数据保护

- **无新报告**：查Actions日志或钉钉告警；重试复用有效进度、重拉过期数据。已有新数据但未发布时，先完成正常运行，不能直接`rerender`旧一期。
- **商品未入选**：依次查范围、量门槛、日数据、评分、时效、基准和排除原因；区分“未覆盖”和“已覆盖未达标”。
- **通知/链接失败**：核对同一机器人的Webhook、SEC配对，再查网络、链接密钥。换域名用`REPORT_BASE_URL`：线上填Actions Variables，本地填`.env`。
- **存放与权限**：源码在`main`，线上加密数据、报告在`site`分支；公开站点不得含`data/`。链接`#k=`后为该期解密密钥，分享完整链接即授予该期访问权限。
- **备份与提交**：备份`REPORT_KEY`，丢失无法恢复历史。`.env`、本地`site/`、`out/`、解密明文不得提交源码分支。密文触发推送保护可用`python -m radar reseal`重新加密。
