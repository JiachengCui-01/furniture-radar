# 家具爆品雷达

基于卖家精灵数据，自动监控亚马逊美国站家具市场，发现增长商品、持续热销商品和可参考的开发方向，生成加密报告并推送到钉钉群。

默认监控板材、实木、铁木为主的柜类、桌类、床架、置物架等；剔除沙发、床垫、椅子、软包、布艺抽屉、塑料及配件等不符合范围的商品。

**默认两周一期，卖家精灵调用上限每月 2,000 次。** 系统每天北京时间 08:17 检查，距上次成功运行满 14 天才采集新一期数据。具体范围、阈值和预算以 [config.yaml](config.yaml) 为准，逐条判定说明见 [判定规则说明.docx](判定规则说明.docx)。

## 报告看什么

| 内容 | 主要依据与用途 |
|---|---|
| 突然爆火 | 近 7 或 14 天销量、BSR 明显改善，且通过增长形态、断货、大盘和回落检查；区分新品爆发、老链接重新起量、稳在高位和仍在上涨 |
| 潜力产品 | 上架 30～180 天、评论较少，近 28 天及近 7 天均保持增长；有足够完整月份时验证月度增长 |
| 持续热销 | 最近 4 个自然月中至少 3 个月达到子类目销量门槛，并检查销量规模、波动、月趋势和近期销量；符合条件的头部商品可用月度名单补判 |
| 上升中 | 尚未归入爆火或潜力，但近 28 天及近 7 天均达到增长要求，且没有回落、断货恢复等排除情形 |
| 外观与工艺依据 | 从增长商品提取主材质、风格、造型、工艺、颜色和功能卖点，对比头部或持续热销商品，区分明显更多、常见及也有的特征 |
| 开发方向 | 按增量销售额排列符合条件的子类目，提供产品画像、价格、包装、FBA 配送费和不同品牌的参考商品；没有画像时说明原因 |
| 异常信号与上期对比 | 列出评论、评分、销量等异常依据，以及商品本期进入、继续上榜或退出的情况，供人工复核 |

增长商品 = 突然爆火 + 潜力 + 上升中。爆火、潜力和开发方向优先按估算的月增量排序；异常信号用于提示核查，不能直接认定刷单。

## 关键判断口径

- **来源与覆盖**：判定使用卖家精灵名单、日数据及补充查询。增长机会主要从近 30 天销量 ≥300 件或销售额 ≥4 万美元的全市场名单初筛，再按预算拉日数据；同一父体去重。默认评分下限 4.0，评论不足 100 条时为 4.2。
- **时效与缺失**：日数据落后本期最新数据日或本期判定日期超过 2 天，不判增长；整批数据过期时停止发布。缺失基准保留为未知，不能当作零销量。短对比期会标注天数，月度证据不足会注明尚未验证。
- **窗口与形态**：七天、十四天窗口分别完成所有检查，再从达标窗口选最强的。断货恢复、短时脉冲和正在回落不算增长；老品换链接不按真新品处理。
- **月份与市场影响**：月度规则按真实自然月计算，缺月不拿旧月份补齐，未来月份不参与。大促日需数据印证，比较时剔除；增长倍数需跑赢上涨的品类大盘。不做季节性调整。
- **修订校正**：卖家精灵可能回头修订近期销量。仅在日期对齐的共同有效样本不少于 30 个、且证据支持本期偏高时校正；证据不足时保留原始口径并提示。
- **品牌与特征**：独立品牌支持只统计已知品牌，未知品牌商品仍保留在样本中。开发方向两边按品牌等权对比；头部已知品牌不足 10 个时只列共同特征。
- **增量与成本**：增量基准未知的不计入合计；老链接恢复、回到旧水平等情形不计正增量。销量、增量和 FBA 费用均为估算，实际开发还需结合工厂报价、运输、广告及退货等成本核算。

## 本地试用（Windows）

使用 Python 3.11，在仓库目录打开 PowerShell：

```powershell
python -m pip install -r requirements.txt
python -m radar demo
```

演示使用模拟数据，不调用卖家精灵或钉钉；用浏览器打开生成的 `out/demo/report.html` 即可预览。

真实运行前，将 [.env.example](.env.example) 复制为 `.env` 并填写所需密钥；已有 `.env` 时直接编辑。随后执行 `python -m radar run`。本地数据保存在 `site/`，与 GitHub 的 `site` 分支相互独立。

### 密钥配置

本地写入 `.env`；线上写入仓库 **Settings → Secrets and variables → Actions → Secrets**。

| 名称 | 用途与获取方式 |
|---|---|
| `SELLERSPRITE_SECRET_KEY` | 真实采集必填，在 [卖家精灵开放平台](https://open.sellersprite.com) 获取 |
| `REPORT_KEY` | 数据和报告加密必填；安装依赖后运行 `python -m radar keygen` 生成，**务必另行备份** |
| `DINGTALK_WEBHOOK`、`DINGTALK_SECRET` | 推送钉钉时填写；在群内添加自定义机器人，安全设置选择“加签”，保存 Webhook 和 SEC 开头的密钥 |
| `DEEPSEEK_API_KEY` | 可选，在 [DeepSeek 平台](https://platform.deepseek.com) 获取；用于文字简报和主图识别。未配置时使用模板简报和已有的非视觉依据 |

## 部署到 GitHub

1. Fork 仓库并在 **Actions** 页启用工作流。按上表添加仓库 Secrets。
2. 在 **Settings → Pages → Build and deployment** 中，将 Source 设为 **GitHub Actions**。
3. 打开 **Actions → 家具爆品雷达 → Run workflow**，`mode` 选 `run`。可用 `force` 忽略运行间隔、`notify` 控制钉钉推送、`budget` 覆盖本期调用预算。
4. 完成后在钉钉卡片中打开报告。之后每天检查、满 14 天运行；首次运行及补齐历史名单时，耗时取决于调用数量、限流和主图识别量，以 Actions 进度为准。

Windows 用户也可安装 [GitHub CLI](https://cli.github.com)，执行 `gh auth login` 后，在仓库目录运行密钥配置脚本：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_secrets.ps1
```

脚本可读取本地 `.env`；缺少 `REPORT_KEY` 时会生成并保存到 `.env`，请备份。

**添加更多钉钉群**：每个群新增一个 Secret，名称使用 `DINGTALK_ROBOT_1` 至 `DINGTALK_ROBOT_5`，值为 `Webhook地址,SEC密钥`。可与原有 Webhook 配置同时使用；删掉对应 Secret 即停止向该群推送。工作流已预留 5 个，更多群需同步修改工作流。本地支持 `DINGTALK_ROBOT_<名字>`。

### 常用操作

| 命令或操作 | 用途 |
|---|---|
| `python -m radar run --force --notify` | 忽略运行间隔，真实采集并推送钉钉；会消耗卖家精灵调用 |
| `python -m radar rerender` | 用已保存数据重生成最近一期报告，不调用卖家精灵，报告链接不变；线上在工作流中选 `mode: rerender` |
| `python -m radar notify` | 将最近一期报告推送到钉钉 |
| `python -m radar test-dingtalk --with-key` | 发送测试卡片，检查机器人及链接密钥片段是否保留 |
| `python -m radar status` | 查看本地期数、调用记录和历史数据概况 |
| `python -m radar decrypt site/reports/某期日期.html` | 将报告解密到本地；也支持 `site/data/state.enc` |
| `python -m radar reseal` | 重新加密，内容和链接不变；用于 GitHub 推送保护误判密文时的恢复 |
| `python -m radar --help` | 查看全部命令；各命令后加 `--help` 查看参数 |

验证代码时先运行 `python -m pip install -r requirements-dev.txt`，再运行 `python -m pytest -q`。测试不会调用真实卖家精灵或钉钉。

## 常用参数与预算

所有非机密配置见 [config.yaml](config.yaml)，密钥放 `.env` 或 GitHub Secrets。

| 配置项 | 调整内容与当前默认值 |
|---|---|
| `scope.*` | 类目范围、标题排除规则、额外追踪类目 |
| `pool.*` | 追踪名额、全市场门槛和初筛条件；降低门槛会增加调用需求 |
| `schedule.min_days_between_runs` | 运行间隔，默认 14 天 |
| `budget.split`、`monthly_cap`、`max_per_run` | 默认 `even`：本月剩余额度按剩余期数分配；每月上限 2,000、本期上限 2,500。`per_run` / `bootstrap_run` 仅在 `fixed` 模式生效 |
| `budget.review_checks`、`material_lookups`、`monthly_list_calls` | 每期评论核查最多 15 个、材质查询最多 30 次、往月名单补齐最多 50 次 |
| `thresholds.*` | 评分、爆火、潜力、热销、异常、数据时效、外观工艺和开发方向等规则 |
| `llm.*` | 文字简报、主图识别开关及模型；识别结果会缓存，模型费用另计 |
| `report.*`、`notify.*` | 报告标题、网址、保留期数及推送内容；默认保留最近 60 期报告 |

调用次数按北京时间的自然月记账。首次运行需发现类目、建立基准，往月名单会分期补齐；之后按预算优先追踪上期上榜商品、子类目头部和初筛机会。实际覆盖数量随市场及预算变化，报告的数据说明会列出当期覆盖情况。

若与 AI 工作台共用卖家精灵密钥，账户额度由两边共同消耗；本项目只记录自身调用，配置预算时需为其他用途留出额度。

## 失败恢复与常见问题

| 情况 | 处理方式 |
|---|---|
| 本期没有生成报告 | 查看 Actions 日志或钉钉告警。核心阶段额度耗尽、持续连接失败、刷新比例不足、整批数据过期或程序错误时停止发布；已获取的数据及调用次数会保存，旧报告保留 |
| 下次运行如何接续 | 复用仍有效的已获取数据；整批过期数据会重新拉取。已保存更新数据但尚未发布新一期时，暂停 `rerender`，待正常出新一期后恢复 |
| 只想更新报告样式或规则 | 线上运行 `mode: rerender`，按原报告日期重生成；不会重新采集数据 |
| 有爆品没出现在报告 | 检查类目、标题、评分、全市场门槛和本期预算覆盖；刚起量或短期增长商品可能尚未进入名单或追踪池 |
| 钉钉加签或关键词错误 | 核对 Webhook 与 SEC 密钥是否属于同一机器人；使用关键词模式时设置关键词“雷达” |
| 报告打不开或网址需更换 | 检查网络和链接密钥；使用自定义域名时，线上在仓库 Actions **Variables** 设置 `REPORT_BASE_URL`，本地在 `.env` 设置同名变量 |

## 数据与密钥保护

- 源码放在 `main`，线上加密状态和报告保存在 `site` 分支；发布的网站不包含 `data/` 目录，首页只列报告日期。
- `REPORT_KEY` 是主密钥，每期报告有独立密钥，位于链接的 `#k=` 片段。该片段不随页面请求发送给服务器；打开报告后会从地址栏移除。分享链接即授予该期报告的访问权限。
- 往期报告从对应钉钉消息打开，也可在报告页手动输入密钥。**丢失主密钥后无法恢复历史数据，不能直接换一把新密钥继续解密旧数据。**
- `.env`、本地数据和输出目录已被 Git 忽略；解密导出的明文也应保留在本地。公开 Actions 日志仅输出汇总，调试时避免打印商品数据或密钥。
