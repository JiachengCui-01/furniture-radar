# 家具爆品雷达

基于卖家精灵数据监控美国站家具，筛选增长、持续热销和异常商品，提炼开发方向，生成加密报告并推送钉钉。

**运行间隔14天，每月调用上限2,000次。** 每天北京时间08:17检查运行条件。参数统一配置在 [config.yaml](config.yaml)，离线规则见 [Word手册](判定规则说明.docx)。

## 判断规则

每次采集、判定和生成报告均须遵守以下规则。调整阈值时，须同步配置、实现、报告说明和两份文档。

## 1 范围与候选规则

监控范围限美国站家具、办公家具中的板材、实木、铁木柜桌、床架和置物架；排除沙发、床垫、椅子、软包、布艺抽屉、塑料和配件。类目名须命中保留词且不命中剔除词，商品标题另行过滤；面料词须结合品类，配件词须结合家具名词位置判断。子类目商品数须 ≥800，最多追踪30类。

**机会候选须满足近30天销量 ≥300件或销售额 ≥4万美元，并按父体去重。** 初筛只决定日数据采集资格，入榜还须通过对应板块规则。

- 初筛满足任一即可：比约28天前快照增长 ≥15%；上架 ≤180天且未跌；近14天短期日均倍数 ≥1.3。新进名单无基准时可保留候选，不得直接认定从零增长。
- 无合适快照时，用上月名单或21～52天前快照；基准年龄 ≤23/36/52天，增长线分别为10%/15%/10%。月度基准下近7天BSR改善 ≥20%也可触发。月销量须先统一天数口径，代表子体更换须按父体匹配。
- 采集按优先级分配预算：上期爆火、潜力、异常最多300个 → 子类目头部30个 → 初筛机会；总池上限3,000。新进名单中BSR改善 ≥20%者优先，其余综合基准增长和短期持续性排序。
- 月度发现取每类销售额前50；新品补查取销量最大的12类，每类最多30个、月销售额须 ≥2万美元。
- 同类目相邻月份共同商品 ≥5且 ≥50%月销量完全相同时，须标记名单可能未更新完，并重拉受影响类目。

参数：`scope`、`discovery`、`pool`。实现：[发现](radar/discovery.py)、[初筛](radar/universe.py)、[追踪](radar/tracking.py)。

## 2 通用判定规则

**主标签必须依次判断：评分偏低 → 异常 → 爆火 → 潜力 → 热销 → 观察。** 上升中只附加于观察或热销商品；增长样本 = 爆火 + 潜力 + 上升中，须去重并排除低分、异常。分类、分数和金额须由程序计算，文字简报不得改变入榜结果。

| 项目 | 必须遵守的边界 |
|---|---|
| 评分 | ≥4.0；已知评论数 <100 时 ≥4.2。无评分不直接判低分，评论数未知用一般评分线；日数据优先于名单 |
| 时效与发布 | 日数据落后批次最新日或判定日中较晚者 >2天，不得判增长；整批过期须停止发布。刷新须 ≥计划60%且至少1个 |
| 缺失与零 | 未知不补零；在卖观察按实际均值。断货过滤后无在卖观察时，须有 ≥7 个明确零日、其他非大促有效销量也全零，才补认零基准 |
| 断货与短基准 | 增长基准剔除 BSR 缺失或 ≥1,000,000 的日子；潜力、上升中再剔除连续 ≥3 个明确零日，大促不拆断零段。在卖 <14 天标注，增量另作保守处理 |
| 自然月 | 热销及潜力只看已结束月份；缺月保留位置，不拿旧月补位。趋势对 ln(月销量+1) 按真实月距拟合，换算月增长率；不足 2 个有效月不估计 |

### 大促和市场影响

大促日：前 14 天至少 70% 有数据、销量中位数 ≥3 件的商品中，当天至少 40 个合格样本，销量达自身基准 1.8 倍的占比 ≥30%；相邻日 ≥15% 可延伸，登记活动也需 ≥15% 的数据印证。日度比较剔除确认的大促日，不作季节调整。

大盘：同类目至少 10 个共同商品，销量倍数取中位数、统一折成 28 天，最高 2 倍。大盘 >1 时，爆火、潜力、上升中的增长倍数先除以大盘再过线；从零起量不扣，大盘 <1 不放宽。

销量修订须有 ≥30个日期对齐共同商品、历史修订幅度 ≥2%。`correct`模式仅在历史为下调、近期窗口偏高证据足够时校正；偏高确认线为`1+(1/历史修订中位数−1)×0.5`。证据不足须保留原值并提示；`tag`模式只提示，不改金额和排序。

参数：`thresholds` 的评分、时效、断货、`events`、`tide`、修订项。实现：[窗口](radar/series.py)、[大促](radar/detect/events.py)、[综合判定](radar/analyze.py)。

## 3 爆火潜力与上升中

三类均排除低分、异常、过期、断货恢复、已识别短时脉冲及近期回落。潜力、上升中须同时保持 28 天与最近一周增长，防止旧涨幅撑高均值。

### 突然爆火

近 7 天、14 天分别与各自此前 28 天比较；**任一窗口独立通过全部条件即可，取合格窗口中最强者**。

- 普通增长：日均 ≥3 件；销量倍数 ≥2；近期/基准 BSR 中位数 ≤0.5；扣上涨大盘后销量倍数仍 ≥2。
- 从零起量：基准已知且日均 <0.5 件，近期日均须 ≥`max(30，类目第20名月销量÷30×25%)`。旧 BSR 缺失可豁免排名倍数，有旧值仍检查；老品换链接不走此通道。年龄 ≤180 天称新品爆发，超龄或年龄未知称老链接重新起量。
- 形态取最近 7 个非大促观察日，最多回看 14 个日历日。正增量最大的 2 天占比 ≥60%，先排为脉冲；其余从零起量可确认。普通增长还须满足：至少 5 天销量 ≥基准 1.5 倍，且近 3 天/7 天日均在 0.85～1.15；**或**近 7 天/前 7 天日均 ≥1.15，且近 3 天高于近 7 天。
- 近期价格中位数下降 ≥15% 只标“降价驱动”，不取消入榜。未过确认量或形态不稳只提示，不算爆火。

### 潜力与上升中

| 条件 | 潜力须满足 | 上升中须满足 |
|---|---|---|
| 成熟度 | 已知上架 30～180 天；已知评论数 <300 | 不限年龄、评论数 |
| 近 28 天日均 | ≥2 件 | ≥3 件 |
| 28 天及最近一周 / 旧 28 天在卖日均 | 两项扣上涨大盘后均 ≥1.2 | 两项扣上涨大盘后均 ≥1.3 |
| 月趋势 | 最近 3 个已结束月中，上架月之后有 ≥2 个有效月时，月增长 ≥15%；不足则标“尚未验证” | 不要求 |
| 特殊限制 | 排除老品换链接 | 只统计未入爆火、潜力的观察或热销商品 |

最近一周指近 7 个非大促观察日，最多回看 14 日；基准未知或为零时不靠无限倍数通过。爆火、潜力先按月增量降序，同额分别看爆发强度、增长；上升中不重复计入前两类。

参数：`thresholds.surge`、`potential`、`rising`。实现：[准入与形态](radar/detect/rules.py)、[逐窗口过滤和排序](radar/analyze.py)。

## 4 持续热销

类目门槛须取销售额、销量头部名单合并、按父体去重后的月销量第20名；不足20个取末位，无样本不得设门槛。报告须注明这是样本门槛，不得表述为逐月全市场排名。

以下条件**同时满足**：

1. 最近 4 个已结束自然月至少 3 个月达到类目门槛，且各达标月销量 ≥150 件或销售额 ≥2 万美元。
2. 最近 6 个日历月已知月销量的 CV（标准差/均值）≤0.35；最近 3 月趋势可算时每月 ≥−15%。缺月保留缺口，趋势不可算不单独否决。
3. 近 28 天日均 ≥最近 6 月已知月份平均日均的 70%，必须有近期证据。

按 6 月已知月销量均值降序；日度回落可保留热销并提示，不算仍在增长。

**月度补判须同时满足**：未纳入日数据追踪、与已追踪商品不同父体、连续6月均入对应类目销售额或销量前50、有报告期有效近30天销量。近期日均按销量÷30，并按大促、修订规则处理后再判热销。仅有月度数据时不得画日走势图、判日度回落或计入日数据追踪数；异常达线须转异常并标“长期头部”，不得重复计热销。

参数：`thresholds.hot`。实现：[热销规则](radar/detect/rules.py)、[月度补判](radar/analyze.py)、[名单补齐](radar/monthly_lists.py)。

## 5 回落恢复与换链接

### 回落任一成立即撤销增长

- 近 3 天日均 <近 28 天最高连续 3 天日均的 75%，且 <再之前 3 天的 90%。
- 近 7 天销量中位数 <前 7 天的 85%。
- 近 7 天峰值后至少连续 3 天未回升，最后一天 ≤峰值 70%。

### 断货恢复与老品换链接

**断货恢复须同时满足**：爆火基准期明确零销量或BSR达断货线的天数 ≥`max(7，窗口有效长度×25%)`；更早90天有 ≥14个非零销售日，且其日均 ≥近期日均一半。不得把缺数据当作断货证据。

**老品换链接**：上架 ≤180 天，评论/本 ASIN 已观测累计日销量 ≥50%；或该比例 ≥15%，且满足以下任一：首个销售日起一周日均 ≥5 件且 ≥最近 7 天一半；首次达到该量级后的一周仍维持，前一周日均 ≤后一周 10%；有效近 60 天评论量不足按总评论推算应有量一半。

换链接不判潜力或从零新品爆发，不以继承评论给留评率、新品评论比计分；仍可凭稳在高位、上涨或上升中证据入选。基准涉及开卖首周只标注；短基准增量见第 9 节。

参数：`thresholds.momentum`、`relist`、恢复项。实现：[规则](radar/detect/rules.py)、[历史高位检查](radar/analyze.py)。

## 6 异常计分

**异常总分 ≥3分才入榜，≥5分列为较高风险。** 须按总分、近28天日均降序，低评分优先取得主标签。异常分只用于复核，不得表述为刷单概率；不得因空榜认定没有异常，也不得为填榜降低证据要求。

| 信号 | 计分条件 | 分值 |
|---|---|---|
| 留评率 | 扣 Vine 后新增评论 ≥10，留评率 ≥max(6%，类目中位数×3) | +2 |
| 新品评论比 | 上架 ≤90 天、总评论 ≥20；扣 Vine 后评论/完整累计销量 ≥10% | +2；已有留评率分时 +1 |
| 评论增速 | 扣 Vine 后新增 ≥10，完整区间销量为零，或新增评论/销量 ≥max(15%，类目留评率×3) | +2；前两类已计分时 +1 |
| 评分跳升 | 相比 45 天内前次有效观察提高 ≥0.2，总评论 ≥50 | +1 |
| 销量脉冲 | 最近 30 天出现 1～3 天冲高，起点 ≥前28天销量中位数×3 且 ≥6 件/天；之后间隔 ≥3 天、最多看 7 天，可用日均 <基线1.3倍；排除大促 | +1 |
| 评论集中 | 样本 ≥10，最多的 3 天占比 ≥30%，且条数严格高于同样样本量、跨度的均匀随机分布99%分位 | +2 |
| 非验证购买 | 有明确验证标记的样本 ≥10，其中非验证比例 ≥50% | +1 |

### 不计分与抵扣

- 评论与销量须保持同一父体口径，不得再除以变体数。月新增评论 >总评论×1.05+5时，该留评率不得计分；有效核查表明评论继承或已识别换链接时，对应留评率、新品评论比不得计分。
- 评论增速基准取此前 45 天记录最高评论数，无则回退前次有效观察，避免评论数回弹被当新增。确认父体/变体合并时，相关增速不计。
- 增速销量区间每天须完整、非负且有限，缺一天不算；明确全零才能计“有评论无销量”。新品累计销量须覆盖上架月至截止月，月度不齐再用完整日数据，仍不齐则不算；未来月份忽略。
- Vine须优先按有效样本比例扣除；无可用比例且上架 ≤90天时，按项目30条额度保守扣减，扣前已达线者须保留待核查资格。Vine样本占比 ≥30%、变体合并、大促脉冲只作解释标签，不得加分。

参数：`thresholds.fake`。实现：[计分与抵扣](radar/detect/fakehot.py)、[销量完整性](radar/series.py)。

## 7 核查证据

**每期评论与详情共 15 次，内含未上榜且已有 ≥2 分候选的预留 5 次，不足归还。** 评论上涨 ≥30% 且无新鲜详情时优先查父体/变体；评论核查顺序：可疑上榜 → 报告点名及参考候选 → 未上榜 ≥2 分 → 其他爆火/潜力 → 可能 Vine 抵扣新品。同级综合异常分、强度、销售额排序，仍保障预留名额。

- 样本取截至商品数据日约 60 天的最新评论，查询和过滤边界一致。部分页集中度按最早样本至截止日跨度、至少 7 天；确认完整时按 60 天。非空响应全部被日期过滤，不保存成新核查。
- 验证购买只认明确真/假，缺失须保留未知；有效标记 ≥10才算非验证比例，Vine标记须完整才用比例。零样本但总量非零/未知不得作有效核查；复用核查时，缺少标记样本数的比例不得沿用。
- 取得日期距判定日须 0～13 天，恰好 14 天失效；评论样本截止日也须新鲜。已知父体改变，或变体变化 ≥max(2，旧数30%)，评论核查失效；详情保留前后快照。
- 历史回放不得使用判定日之后取得的核查或身份；取得日与数据截止日须分别保存。更新前须保留父体快照，同日评分变化须入库，缺失不得覆盖同日有效值。

参数：`budget.review_checks`、`review_checks_unlisted`。实现：[排队与样本](radar/verify.py)、[时效与身份](radar/evidence.py)。

## 8 外观工艺与主材质

标题共性须比较增长商品与全部月度头部，至少需3个增长、20个头部。主图样本取势头前50个增长，对照最多40个非增长的持续热销商品，另补开发方向所需样本；颜色有主图时须优先主图。样本不足或来源冲突时，不得强行形成趋势结论。

**外观每项至少 2 个商品、2 个已知品牌支持。** 未知品牌保留在商品占比分母，不作独立品牌证据。

| 档位 | 判定条件 | 允许的结论 |
|---|---|---|
| 更多 | 标题占比 ≥10%、0.5计数平滑后相对倍数 ≥1.3；或主图比对照高 ≥10 个百分点 | 相对更突出 |
| 常见 | 未入更多、增长占比 ≥30% | 共同特征 |
| 也有 | 未入前两档、占比 ≥10% | 有一定支持 |

有效标题与主图一方说更多、另一方说更少，三档均不列。更多按占比差排序，两源支持适当前置，每维最多 6；常见最多 3。结构化共性需 ≥2 个商品、占比 ≥20%、平滑倍数 ≥1.5，最多 10 条；关键词需至少 3 个支持（增长样本 <20 时为 max(2，15%样本向上取整)）、平滑倍数 ≥2，最多 15 条，不证明词语带来增长。

主材质每商品只计一类，取证顺序须为：**Material属性 → 标题具体材质 → 主图 → 笼统木质**。增长与持续热销须分组统计，未知保留分母，不套外观“更多”判定。属性查询每期最多30次，复用结果须注明来源；不得把缺属性当成没有该材质，或仅凭木纹判实木。

参数：`thresholds.appearance`、`llm.vision_*`。实现：[标题](radar/detect/design.py)、[共性合并](radar/detect/traits.py)、[材质](radar/materials.py)。

## 9 开发方向与金额

### 方向及产品画像

同类目须有 **≥2个增长商品、≥2个已知品牌**才形成方向；按月增量总额排序，同额依次看品牌数、增长数、爆火数和势头。完整报告按配置上限展示，0表示全部，摘要取前5；缺少共同特征及明确材质时不得拼凑画像，须列明原因，高增量缺画像须另提示。

头部取同类目月销量前 30，排除增长商品及同父体。头部 ≥10 个已知品牌才比较；若有主图的头部品牌也 ≥10，两边用标题+主图，否则两边仅标题。头部不足只列共同特征。

- 外观两侧先算品牌内部商品占比，再对已知品牌等权平均。比头部多：≥2 品牌支持，品牌均占比高 ≥20 个百分点且 ≥头部1.5倍；基本款：≥2 品牌、均占比 ≥50%且未入更多。每维每档最多 3 项。
- 主材质按品牌是否有该材质计支持，≥半数且 ≥2 品牌才列，不直接作头部优势。价格取有效值范围，≥3 个才给中位数；参考选异常分0、不同已知品牌的最多2个，不足少列。

### 金额和成本

月销售额 = 近28天日均×商品售价×30；月增量 =（近28天日均−旧28天在卖日均）×商品售价×30。两项须采用同一售价，统一大促、修订口径；未知基准不得计入合计，正常负增量须保留。以下增量按0并注明原因：

- 换链接且旧28天无在卖基准或在卖 <14 天；老链接重新起量；上架 >180 天且旧28天在卖 <14 天。基准未知仍优先按无法估算处理。
- 近期水平未超旧基准之前56天内、在卖 ≥14天的历史连续28天最高日均。爆火须用所选7/14天水平核对，其余增长用28天。
- 无售价。

包装必须使用包装尺寸和重量，不得用组装尺寸替代；各指标只按自身有效样本取中位数。体积按英寸长×宽×高÷1,728得立方英尺，再×0.0283168得立方米，重量统一磅。FBA占售价须先逐商品计算再取中位数。销量、销售额和FBA须标为估算；利润核算必须另计采购、头程、佣金、仓储、广告和退货等成本。

参数：`thresholds.directions`、`short_base_days`、`recovery_days`。实现：[方向](radar/detect/directions.py)、[金额](radar/analyze.py)、[包装](radar/shipping.py)。

## 10 对比与发布规则

- **上期对比须按标签定义**：依旧爆火=连续两期爆火；新进入=报告期板块与上期不同；不再爆火=上期爆火、报告期仍追踪但为观察/低分。转其他板块须另列，未追踪不得认作回落，新增月度覆盖须单列补判。回看上期须标明回看；上期提示待修订时，须复核全部上期增长商品。
- **数据问题须提示**：增长商品变体增加 ≥30%且 ≥2个；名单与日销量均 ≥60件但差 ≥2倍；近28天缺 ≥7天。近10天出现广泛BSR改善（≥40样本、历史BSR≤30万、改善到1/1.8的占比 ≥10%、连续 ≥2天）须提示销量可能待修订。上述提示不得直接替代分类规则。
- **调用须受预算约束**：运行间隔14天、每月上限2,000次，剩余额度均分剩余期数，每期最多2,500次；核查15、材质30、月度名单补齐50。须按北京时间自然月记账，共享密钥须另为其他服务预留额度。

实现：[上期对比](radar/detect/diff.py)、[数据标签](radar/analyze.py)、[文字简报](radar/narrative.py)。

## 运行与部署

### 本地运行

Python 3.11，在仓库目录执行：

```powershell
python -m pip install -r requirements.txt
python -m radar demo
```

打开`out/demo/report.html`预览演示。真实运行须复制 [.env.example](.env.example) 为`.env`并填密钥，再执行`python -m radar run`；已有文件直接编辑，不得覆盖密钥。本地`site/`须与线上数据分别管理。

| 密钥 | 用途 |
|---|---|
| `SELLERSPRITE_SECRET_KEY` | 真实采集必填，[卖家精灵开放平台](https://open.sellersprite.com)获取 |
| `REPORT_KEY` | 加密必填，`python -m radar keygen`生成，必须备份 |
| `DINGTALK_WEBHOOK`、`DINGTALK_SECRET` | 钉钉推送；群机器人选加签，保存Webhook和SEC密钥 |
| `DEEPSEEK_API_KEY` | 可选，[DeepSeek](https://platform.deepseek.com)获取；文字简报与主图识别，无密钥用模板和非视觉依据 |

### GitHub部署

1. Fork后启用Actions，在仓库 **Settings → Secrets and variables → Actions → Secrets** 配置上述密钥。
2. **Settings → Pages → Build and deployment** 的Source选 **GitHub Actions**。
3. **Actions → 家具爆品雷达 → Run workflow**，`mode: run`；`force`忽略间隔、`notify`控制推送、`budget`覆盖本期预算。完成后从钉钉卡片打开报告。

Windows可先 `gh auth login`，再运行 `powershell -ExecutionPolicy Bypass -File scripts\setup_secrets.ps1` 配置Secrets；脚本可读取`.env`，缺`REPORT_KEY`时生成并保存，仍需备份。多群增加 `DINGTALK_ROBOT_1`～`5`，值为`Webhook地址,SEC密钥`；更多群同步改工作流。

### 常用操作

| 操作 | 命令或入口 |
|---|---|
| 真实采集并推送，消耗调用 | `python -m radar run --force --notify` |
| 用已保存数据重生成，不消耗调用 | `python -m radar rerender`；线上`mode: rerender` |
| 补发通知 / 测试机器人 | `python -m radar notify` / `python -m radar test-dingtalk --with-key` |
| 查看本地数据 / 全部命令 | `python -m radar status` / `python -m radar --help` |
| 验证代码 | 安装`requirements-dev.txt`后运行`python -m pytest -q`，不调用真实服务 |

配置职责：`scope/discovery/pool`管范围与采集，`thresholds`管判定，`schedule/budget`管间隔与预算，`llm`管模型，`report/notify`管报告与通知。报告按保留期数清理（60期）；模型费用须另计。

## 故障恢复与数据保护

- **发布失败**：须查Actions日志或钉钉告警。核心采集失败、刷新不足、整批过期时不得发布新报告；须保留旧报告和采集进度，重试仅复用有效数据。数据已更新但新一期未发布时不得`rerender`。
- **排查漏选**：须先核对范围、量门槛和预算，再查评分、时效、基准、排除项；不得仅因空榜认定没有机会。
- **通知与链接**：Webhook与SEC须来自同一机器人；自定义域名须配置`REPORT_BASE_URL`，线上用Actions Variables，本地用`.env`。
- **密钥保护**：源码存`main`，线上数据与报告须加密存`site`分支，公开站点不得包含`data/`。报告密钥须放链接`#k=`片段，分享链接即授予该期访问权限。必须备份主密钥`REPORT_KEY`，丢失后不能恢复历史数据。
- `.env`、`site/`、`out/`不得提交源码分支，解密明文须留本地。密文触发推送保护时可用`python -m radar reseal`重新加密；更多操作见命令帮助。
